# [tool-feedback] visual judge calls grok with a flag that is no longer a prompt file

- Tool: `tools/judge`
- Tool version / commit: recipe checkout before this polish commit (`1586e49` plus the uncommitted judge, which was not edited)
- Take / branch and commit of the game being tested: `archives-shards`, Archives polish, 2026-10-04
- Defect seen on screen: the judge did not score the hall. The command printed `FAIL grok: For more information, try '--help'.`
- Metric the tool reported vs what was actually measured: the tool’s argv is `grok -p --prompt-json <file>`. Current `grok -p` is `--single` and requires the prompt text, so the process exits 1 before a score exists. `--prompt-json` expects a JSON value, not a path (`Invalid JSON` when given the file path). The built prompt is 206613 bytes of compact JSON. One Linux argument cannot exceed 131072 bytes, so passing that JSON on the command line raises `Argument list too long`. A recompressed copy of the same prompt (86445 bytes) did return a score: 4, keep false, matches_refs true.
- How to reproduce: `python3 tools/judge/judge.py --candidate packs/common/archives/art/hall.jpg --ref /tmp/hall-old.jpg`
- Still / screenshot: candidate `packs/common/archives/art/hall.jpg`. Reference is the previous `hall.jpg` (720×1280).
- Short video: no
- Proposed fix: `grok_argv` should match the current CLI, and the prompt has to reach `grok` without one argument over 128 KiB. `tools/judge/selftest.py` currently locks the old argv (`grok -p --prompt-json <file>`), so that assertion would need to move with the flag.
- Confirmation: no secrets, API keys, tokens, or private style prompts.
